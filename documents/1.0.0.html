    1.0.0 — upgrading from 0.5.2

    Version 1.0.0 adds password generation and cryptographically secure random helpers, built on the password requirements of @mantlebee/ts-core 1.0.0, and makes the package tree-shakable. The breaking changes are about how the package is installed and imported, and about the fixes of generateRandomNumber, generateRandomDate and generateRandomStringFromPattern, which now return different values or throw on invalid input.

    1. Breaking changes for 0.5.2 consumers

    1.1 ts-core is a peer dependency

    @mantlebee/ts-core was a regular dependency, pinned to 0.24.1. It is now a peer dependency, ^1.0.0: the project that uses @mantlebee/ts-random installs it, and both packages share the same copy.

    npm install @mantlebee/ts-random@^1.0.0 @mantlebee/ts-core@^1.0.0

    npm 7+ installs missing peer dependencies automatically, but it fails if the project depends on a 0.x version of @mantlebee/ts-core: upgrade it to 1.0.0 first, following its release notes.

    Types such as List and IColor, and classes such as Color, keep coming from @mantlebee/ts-core.

    1.2 Package entry points

    package.json now declares an exports map:

    Import File Types
    import (ES modules) dist/esm/index.mjs dist/esm/index.d.mts
    require (CommonJS) dist/index.js dist/src/index.d.ts

    Each build has its own declarations, so TypeScript with moduleResolution node16, nodenext or bundler resolves the right types for both.

    Everything is still exported by the package root, and each area has its own entry point too, e.g. @mantlebee/ts-random/passwords (see 2.4). Deep imports, such as @mantlebee/ts-random/dist/..., are not allowed anymore: import from @mantlebee/ts-random or from an area.

    1.3 generateRandomNumber fixes

    generateRandomNumber(max, min, decimals) has been fixed:

    • with decimals greater than 0, every value between min and max has the same chance to be generated. Before, the values above max were turned into max, so generateRandomNumber(1, 0, 2) returned 1 about half the time;
    • it throws a RangeError if min is greater than max, if decimals is not a non-negative integer, or if no number with decimals digits is between min and max. Before, it returned a wrong value without errors.

    The functions that use it are affected as well:

    • generateRandomColor(true) returns an alpha between 0 and 1 with 2 decimals. Before, it was 0 or 1 only;
    • generateRandomColor accepts from and to in any order, and every channel can be any value between them. Before, when from was darker than to, the darkest value was never generated: with the default colors no channel was ever 0;
    • generateRandomStringFromPattern throws a RangeError for a repeat range whose min is greater than its max, such as a{12,8}.
    // Before: 0 to 1 with 2 decimals, written with min and max swapped
    generateRandomNumber(0, 1, 2); // always 1

    // After
    generateRandomNumber(1, 0, 2); // eg. 0.42

    1.4 generateRandomDate fixes

    generateRandomDate(endDate, startDate, options) has been rewritten:

    • the result is always between startDate and endDate. Before, the time was set after picking the date, so the result could fall outside the range, e.g. in the future with the default endDate, or 9 times out of 10 for a range of a few hours;
    • around a daylight saving time change, the local times that are skipped, such as 02:00–02:59 on the last Sunday of March in Central Europe, are never generated. Before, they were moved one hour forward, so the result could be after endDate and the following hour was twice as likely. The local times that are repeated are generated at their first occurrence only, and never before startDate;
    • the given dates are never modified and a new Date is always returned. Before, when startDate and endDate were equal, endDate itself was modified and returned;
    • the result has no milliseconds, and each allowed second in the range has the same chance to be generated;
    • the default startDate is 1970/01/01 00:00:00 in local time. Before, it was midnight UTC, which is 1969/12/31 west of Greenwich;
    • it throws a RangeError if a date is invalid, if startDate is after endDate, if a time option is out of its range (hours 0–23, minutes and seconds 0–59) or its ...From is greater than its ...To, or if no date in the range has an allowed time. Before, startDate after endDate was accepted, and an option such as hoursTo: 24 moved the date to the next day.

    1.5 Pattern and chars fixes

    generateRandomStringFromPattern:

    • mm generates the months from 01 to 12. Before, it generated 13–19 as well, and never 10;
    • the chars that are not placeholders (A, a, 0, mm), escape brackets or repeaters are copied as they are. Before, the digits from 1 to 9, the letters, some symbols ([, \, ]) and the non-ASCII chars were removed: "x1-0" returned something like "-2";
    • an escape bracket that is not closed throws a SyntaxError. Before, a plain string was thrown.

    generateRandomStringFromChars keeps the chars outside the BMP, such as emojis, whole, and length counts them as one char. Before, it could return half of an emoji.

    1.6 extractRandomItem and extractRandomItems fixes

    extractRandomItem(items, extractPhysically):

    • with extractPhysically set to true, the extracted item is always removed from the list. Before, the only item of a list with 1 item was returned but not removed;
    • it throws a RangeError with message extractRandomItem: empty list if the list is empty. Before, the RangeError of generateRandomNumber was thrown, with the misleading message min 0 is greater than max -1.

    extractRandomItems(items, extractPhysically):

    • it always returns a new list. Before, with a list of 1 item and extractPhysically set to false, the given list itself was returned, so changing the result changed the given list;
    • with extractPhysically set to false, an item of the list is never extracted twice. Before, each item was picked from the whole list, so the result could contain the same item more than once;
    • the length of the result is random, from 0 to the length of the list, both included, so all the items can be extracted. Before, it was from 0 to the length of the list minus 1, except for a list of 1 item, whose item was always extracted: now the result is empty half the time;
    • it returns an empty list if the list is empty. Before, it threw a RangeError.

    2. What's new

    2.1 Password generation

    generateRandomPassword generates a password that satisfies a list of IPasswordRequirement from @mantlebee/ts-core, by default PasswordRequirementsDefault() (8–30 chars, lowercase, uppercase, number, symbol, no whitespaces).

    import {
      PasswordRequirementIncludesLowercaseLetter,
      PasswordRequirementIncludesSymbol,
      PasswordRequirementLength,
      PasswordRequirementsDefault,
    } from "@mantlebee/ts-core";
    import { generateRandomPassword } from "@mantlebee/ts-random";

    generateRandomPassword(); // 8 chars, eg. "q7}Rk;bN"

    // 24 chars with the default categories.
    generateRandomPassword([
      ...PasswordRequirementsDefault(),
      new PasswordRequirementLength(24),
    ]);

    generateRandomPassword([
      new PasswordRequirementLength(12, 12),
      new PasswordRequirementIncludesLowercaseLetter(),
      new PasswordRequirementIncludesSymbol("-_"),
    ]); // 12 chars, eg. "kd-qe_wnz-ab"
    Name Kind Description
    generateRandomPassword function (requirements?) => string
    GenerateRandomPasswordExceptionCodes object code of the exceptions thrown by generateRandomPassword
    NoAllowedCharsException class no requirement has allowedChars
    UnsatisfiableRequirementsException class the requirements can't be satisfied

    How it works:

    • the password gets one char for each requirement with allowedChars, then chars picked uniformly from the distinct union of every allowedChars, until it is valid for validatePassword;
    • the length is defined by the requirements only (e.g. PasswordRequirementLength): the password is as short as the requirements allow, and never more than 256 chars, to avoid infinite loops when there is no maximum length;
    • the chars are shuffled, so the position of each category is not predictable;
    • it uses Web Crypto only, never Math.random.

    It throws exceptions that extend the Exception of @mantlebee/ts-core:

    • NoAllowedCharsException (code is GenerateRandomPasswordExceptionCodes.NoAllowedChars) if no requirement has allowedChars (e.g. an empty list);
    • UnsatisfiableRequirementsException (code is GenerateRandomPasswordExceptionCodes.UnsatisfiableRequirements) if the requirements can't be satisfied, e.g. a minLength greater than a maxLength, or a PasswordRequirementMatchPassword in the list.

    Moving from the external passwords module — projects that used the external copy of the passwords module, where requirements generated their own chars with generateChar(), import generateRandomPassword (formerly generatePassword) from @mantlebee/ts-random and the requirements from @mantlebee/ts-core 1.0.0, which describe their allowedChars instead:

    // Before
    import { generatePassword, PasswordRequirementsDefault } from "@/passwords";

    // After
    import { PasswordRequirementsDefault } from "@mantlebee/ts-core";
    import { generateRandomPassword } from "@mantlebee/ts-random";

    The exception codes are renamed too: GeneratePasswordExceptionCodes.noAllowedChars and GeneratePasswordExceptionCodes.unsatisfiableRequirements become GenerateRandomPasswordExceptionCodes.NoAllowedChars and GenerateRandomPasswordExceptionCodes.UnsatisfiableRequirements. Their values ("NoAllowedChars" and "UnsatisfiableRequirements") don't change, so checks on the string value of code keep working.

    2.2 Secure random helpers

    They replace the external copy of the random module, with the same behaviour but new names, and they are in the secure folder of the sources. They use Web Crypto (globalThis.crypto.getRandomValues), available in browsers and in Node.js 19+. That's why package.json declares "engines": { "node": ">=19" }: npm warns when the package is installed on an older version of Node.js.

    Name Description
    generateSecureRandomInteger random integer in [0, maxExclusive), without modulo bias
    extractSecureRandomItem random item of a list; throws RangeError if the list is empty
    shuffleSecureRandomItems shuffled copy of a list (Fisher-Yates); the original list is not modified

    Unlike generateRandomNumber, generateSecureRandomInteger excludes the max value, so the result can be used directly as an index of a list.

    import {
      extractSecureRandomItem,
      generateSecureRandomInteger,
      shuffleSecureRandomItems,
    } from "@mantlebee/ts-random";

    generateSecureRandomInteger(6) + 1; // a dice roll, eg. 4
    extractSecureRandomItem(["rock", "paper", "scissors"]); // eg. "paper"
    shuffleSecureRandomItems([1, 2, 3, 4]); // eg. [3, 1, 4, 2]

    The other functions, such as generateRandomNumber and extractRandomItem, still use Math.random: don't use them for secrets.

    Moving from the external random module — the functions have been renamed:

    Before (external random module) After (@mantlebee/ts-random)
    getSecureRandomInt generateSecureRandomInteger
    extractSecureRandomItem extractSecureRandomItem
    shuffleSecure shuffleSecureRandomItems

    2.3 Tree-shakable ES modules

    The package ships ES modules, one file per source module, and declares "sideEffects": false. Bundlers keep only the functions that are imported: import { generateRandomBoolean } from "@mantlebee/ts-random" doesn't bring in the pattern parser nor the password generator.

    2.4 An entry point for each area

    Each area can be imported on its own, from both builds:

    Import Exports
    @mantlebee/ts-random/arrays extractRandomItem, extractRandomItems
    @mantlebee/ts-random/booleans generateRandomBoolean
    @mantlebee/ts-random/colors generateRandomColor
    @mantlebee/ts-random/dates generateRandomDate, GenerateRandomDateOptions
    @mantlebee/ts-random/numbers generateRandomNumber
    @mantlebee/ts-random/passwords generateRandomPassword and its exceptions
    @mantlebee/ts-random/secure generateSecureRandomInteger, extractSecureRandomItem, shuffleSecureRandomItems
    @mantlebee/ts-random/strings generateRandomStringFromChars, generateRandomStringFromPattern

    They matter for CommonJS, which is not tree-shaken: the CommonJS build is now one file per source module too, so require("@mantlebee/ts-random/passwords") loads the password generator and the secure helpers it uses only, while require("@mantlebee/ts-random") loads every area. With ES modules and a bundler, importing from the root is just as small.

    TypeScript resolves the types of the areas with every moduleResolution, node10 included, through typesVersions.

    2.5 Docs not in the package anymore

    The typedoc output is not included in the npm package anymore. The API documentation is published on GitHub Pages, and the release notes are in the repository.

    3. Checklist

    • [ ] Upgrade @mantlebee/ts-core to ^1.0.0 and add it to the project dependencies, if missing.
    • [ ] Replace deep imports (@mantlebee/ts-random/dist/...) with imports from @mantlebee/ts-random or from an area, e.g. @mantlebee/ts-random/passwords.
    • [ ] Import generateRandomPassword, generateSecureRandomInteger, extractSecureRandomItem and shuffleSecureRandomItems from @mantlebee/ts-random instead of the external passwords and random modules, renaming generatePassword, getSecureRandomInt and shuffleSecure.
    • [ ] Replace GeneratePasswordExceptionCodes.noAllowedChars and GeneratePasswordExceptionCodes.unsatisfiableRequirements with GenerateRandomPasswordExceptionCodes.NoAllowedChars and GenerateRandomPasswordExceptionCodes.UnsatisfiableRequirements.
    • [ ] Check that every generateRandomNumber call passes max before min: swapped values now throw a RangeError.
    • [ ] Check that every generateRandomDate call passes endDate before startDate, and time options within their ranges: they now throw a RangeError otherwise.
    • [ ] Check the patterns of generateRandomStringFromPattern that contain letters, digits from 1 to 9 or [\] outside escape brackets: they are now copied instead of removed.
    • [ ] Check the calls of extractRandomItems: the result can now contain all the items of the list, and it can be empty for a list of 1 item.
    • [ ] Handle the Exception thrown by generateRandomPassword when the requirements come from user input or configuration.
    • [ ] On Node.js, use version 19 or later for the secure helpers and generateRandomPassword.
