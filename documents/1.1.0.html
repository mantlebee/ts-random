    1.1.0 — upgrading from 1.0.0

    Version 1.1.0 makes the generated data reproducible: a seeded generator, and a random option in every function that uses Math.random. There are no breaking changes: without the new option, every function behaves as in 1.0.0.

    1. Breaking changes for 1.0.0 consumers

    None. The new parameters are optional and last, and the functions called without them use Math.random as before, with the same distribution.

    2. What's new

    2.1 Seeded generator

    createSeededRandom(seed) returns a generator with the same contract as Math.random, a number in [0, 1) at each call, that returns the same sequence for the same seed, in Node.js and in browsers. It uses mulberry32, which has a 32-bit state and only 32-bit integer operations.

    import { createSeededRandom } from "@mantlebee/ts-random";

    const random = createSeededRandom(42);
    random(); // 0.6011037519201636, at every run
    Name Kind Description
    createSeededRandom function (seed: number) => RandomFn
    RandomFn type () => number, the contract of Math.random
    RandomOptions type { random?: RandomFn }, the options of the helpers
    • seed must be an integer, otherwise a RangeError is thrown. Seeds that differ by a multiple of 2^32, such as -1 and 4294967295, generate the same sequence.
    • The sequence of a seed is part of the API: it is fixed by the tests and won't change in a minor or patch version.
    • Seeded generators are predictable: never use them for secrets.

    2.2 The random option

    Every function that uses Math.random accepts a generator, with one rule: the functions that already have an options object get a random field in it, the others get a last, optional options parameter.

    Function New signature
    generateRandomBoolean (options?: { random?: RandomFn }) => boolean
    generateRandomColor (transparent?, from?, to?, options?: { random?: RandomFn }) => ...
    generateRandomDate (endDate?, startDate?, options?) => Date, random in options
    generateRandomNumber (max, min?, decimals?, options?: { random?: RandomFn }) => number
    generateRandomStringFromChars (chars, length, options?: { random?: RandomFn }) => string
    generateRandomStringFromPattern (pattern, options?: { random?: RandomFn }) => string
    extractRandomItem (items, extractPhysically?, options?: { random?: RandomFn })
    extractRandomItems (items, extractPhysically?, options?: { random?: RandomFn }) 
    import {
      createSeededRandom,
      generateRandomDate,
      generateRandomNumber,
      generateRandomStringFromPattern,
    } from "@mantlebee/ts-random";

    const random = createSeededRandom(42);

    // The same values at every run.
    generateRandomNumber(80, 18, 0, { random });
    generateRandomStringFromPattern("+39 0{3} 0{7}", { random });
    generateRandomDate(new Date(2024, 11, 31), new Date(2024, 0, 1), { random });
    • The values depend on the seed and on the calls made before with the same generator: create one for each fixture, or for each test.
    • generateRandomDate needs a fixed endDate to be reproducible, as its default is now, and it generates local dates, so the result depends on the time zone too.
    • To pass options to a function with positional parameters, give the ones before it as undefined to keep their defaults, e.g. generateRandomColor(false, undefined, undefined, { random }).

    The secure functions, generateSecureRandomInteger, extractSecureRandomItem and shuffleSecureRandomItems, and generateRandomPassword don't accept a generator and keep using Web Crypto only.

    2.3 The seed entry point

    createSeededRandom, RandomFn and RandomOptions are exported by the package root and by the new @mantlebee/ts-random/seed entry point, in both builds, and its types are resolved through typesVersions as for the other areas.

    3. Checklist

    • [ ] Upgrade to @mantlebee/ts-random@^1.1.0: no code change is required.
    • [ ] To make test data, stories or E2E fixtures reproducible, pass { random: createSeededRandom(seed) } to the functions that generate them, and a fixed endDate to generateRandomDate.
    • [ ] Keep using the secure functions or generateRandomPassword for secrets: they don't accept a generator.
